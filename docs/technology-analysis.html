Genesis→账户 / 余额→Bank 转账→区块共识→Validator / Reward

EventStore.sol→DataWritten→RPC / ethers.js→The Graph→GraphQL / React
EventStore 专门通过事件日志写入数据，用来理解“原始读取”和“索引读取”的差异。

02作业 2：EVM 技术分析

目标是理解从合约写入到前端查询的完整数据路径。

核心流程

    ↓
Ethereum Transaction 执行
    ↓
DataWritten Event Log + Transaction Receipt
    ├── provider.getLogs —— 原始 JSON-RPC
    ├── contract.queryFilter —— ethers.js 封装
    └── The Graph mapping —— Subgraph Entity —— GraphQL
    ↓
React + ethers.js + MetaMask EventStore 控制台 :5173

技术栈、作用与学习点

技术 / 名词它是什么在项目中的作用你应该掌握什么
SolidityEVM 智能合约语言编写 EventStore.sol函数、事件、输入校验、Gas 和合约边界
EVM执行智能合约的虚拟机运行 Solidity 字节码合约不是普通后端程序，而是在链上确定性执行
HardhatEVM 开发框架本地节点、编译、测试和部署智能合约开发的完整工程闭环
ethers.js v6JavaScript 区块链 SDK创建 Provider、Contract、Signer 并读取事件前端和脚本如何访问 EVM
JSON-RPC节点的标准请求协议查询 Chain ID、区块、交易和日志区块链节点 API 的底层工作方式
Provider只读连接对象查询区块、余额和事件读取权限和写入权限的区别
Signer交易签名对象通过 MetaMask 签名写入交易钱包如何授权一笔链上交易
Receipt交易执行回执读取交易状态、Gas 和 Event Log如何判断交易真的上链成功

The Graph区块链数据索引协议把 Event Log 转成可查询实体为什么 DApp 需要链下索引层
SubgraphThe Graph 的索引项目定义网络、ABI、Schema 和 Mapping如何为链上事件建立查询模型
GraphQL按字段查询数据的 API 语言查询 dataWrittens 实体排序、过滤、分页和前端数据读取
React + MetaMaskDApp 前端与浏览器钱包连接账户、签名写入、展示三种读取结果钱包连接、Signer、网络切换与事件监听

Storage、Event、Receipt 的区别

概念存放 / 产生位置适合做什么注意点
Storage合约持久化状态保存合约后续还要读取和修改的数据读写成本较高，属于合约状态
Event Log交易执行时产生的日志给前端、索引器和区块浏览器读取合约不能像读取 storage 一样读取历史事件
Transaction Receipt交易执行后的回执验证成功、Gas、区块和日志通常通过交易哈希查询
EventStore 只发出 DataWritten 事件，不保存业务 storage。它是为了专门训练“链上写入 → 链下读取 → 索引查询”的数据链路。

03跨两条作业的技术名词

这些词不属于某一条链，但决定你能不能看懂 Web3 的完整系统。

区块 Block

一批按顺序确认的交易集合。作用：提供时间顺序和共识确认单位。

交易 Transaction

用户请求链执行某个动作。作用：改变余额、质押状态或调用合约。

状态 State

链当前保存的账户、余额和模块数据。作用：交易执行前后进行状态转换。

节点 Node

运行链软件并对外提供接口的进程。作用：接收交易、同步区块、提供查询。

RPC

程序访问节点的协议。作用：让脚本和前端读取区块链，而不是人工操作节点。

索引 Index

把原始事件整理成更适合查询的数据结构。作用：提高历史数据搜索、过滤和分页体验。

链上 / 链下

链上是共识确认的数据；链下是前端、RPC 服务和索引数据库。作用：理解可信边界与系统分工。

本地链 / 测试网

本地链用于快速开发，测试网用于接近真实网络的验证。作用：控制成本、风险和部署阶段。

04你能从项目中学到什么

建议把学习成果分成六层，每一层都对应可以实际验收的能力。

1. 区块链底层

理解账户、余额、交易、区块、状态、共识和节点，而不是只会连接钱包。

2. Cosmos 应用链

能运行自己的链，解释 Genesis、Bank、Validator、Delegation 和 Reward 的关系。

3. 智能合约

能用 Solidity 编写、测试和部署合约，理解函数、事件、Storage、Gas 与权限。

4. 链上数据读取

会从 JSON-RPC、ethers.js Provider、Receipt 和 Event Log 中读取可复核数据。

5. 索引与 DApp

会写 Subgraph Schema / Mapping，通过 GraphQL 和 React 展示历史链上数据。

6. 工程与安全

会区分本地链、测试网和生产网络，保护私钥与 API Key，并用测试和部署证据验收。

05两个作业的目的

两个作业并列存在，是因为它们训练的是不同层次的能力。

作业 1：回答“链怎么运行”

它更接近区块链基础设施和协议层。

  • 从零初始化链的创世状态；
  • 理解账户和余额如何被链维护；
  • 观察交易如何进入区块并改变状态；
  • 理解 PoS 验证者、委托人和奖励；
  • 通过 REST API 和浏览器验证结果。

作业 2：回答“数据怎么被使用”

它更接近智能合约、数据服务和 DApp 开发。

  • 编写合约并产生可查询事件；
  • 比较原始 RPC、ethers.js 和 The Graph；
  • 理解 Provider、Signer、MetaMask 和 Receipt；
  • 用 Subgraph 把事件转换成查询实体；
  • 让 React 前端消费同一批链上数据。

完整学习闭环

01 · 启动运行 Cosmos 应用链或本地 EVM 节点
02 · 写入发送 Bank 交易或调用 Solidity 合约
03 · 确认区块、共识、Receipt 和 Event Log
04 · 读取REST、RPC、ethers.js、GraphQL
05 · 展示React 链浏览器和 EventStore 控制台

06建议学习顺序

  1. 先启动 Cosmos 链，查询区块高度、三个账户和余额。
  2. 完成一笔 Bank 转账，前后对比 Alice 和 Bob 的余额。
  3. 创建 Validator，完成 Delegation，并观察 Reward。
  4. 启动 Hardhat 节点，部署 EventStore 并写入一条事件。
  5. 分别使用 getLogs、queryFilter 和 Receipt 读取同一条数据。
  6. 部署到 Sepolia，用 Infura 和 Alchemy 读取同一合约。
  7. 配置 Subgraph，通过 GraphQL 查询，再让 React 控制台展示。

每一步都要回答四个问题：谁发起？数据写在哪里？谁确认？如何验证？

07安全边界

  • 私钥、助记词、API Key 和完整 RPC 密钥 URL 不进入仓库。
  • 测试网钱包与真实资产钱包完全隔离。
  • EVM 写交易由 MetaMask 签名，Cosmos 浏览器保持只读。
  • VITE_* 变量会进入前端构建产物，不应放真正的秘密。
  • RPC 读取结果、Subgraph 索引结果和真实部署结果要分别验证。
